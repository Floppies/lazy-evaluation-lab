# B02.8 audit: Surface-to-Core desugaring

Date: 2026-10-19. Scope: repository state after the iterative Surface validation fix, plus the changes recorded below. No evaluator was implemented or used. No Git commit was created.

## Executive summary

**Ready for B02.9 with documented limitations.** B02.8 is complete for parser-produced Surface v0.1 trees under the validate-before-lowering contract. Every supported construction has a Core representation. No static first-match, binder-capture, parameter-order, or unintended-evaluation defect was found for those inputs. This is a structural and static audit, not a proof of runtime equivalence or experimental neutrality.

The preceding Surface validation fix is present and effective. Surface validation, lowering, and Core validation handle the 2,000-term addition pipeline. Additional tests exercise 2,000-deep manual trees, 2,000-element lists, 2,000 parameters, 2,000 global groups, and a 2,002-equation group. All 120 pattern sequences of lengths one through four preserve static first-match routing for both list constructors.

One implementation defect was fixed: duplicate Core bindings with malformed location metadata could raise `AttributeError` while producing a validation diagnostic. Documentation claiming desugaring was unimplemented was corrected using the later sections as the current contract, as requested.

Before implementing name resolution, decide whether unresolved names in unreachable source equations must be diagnosed. Operational alias behavior, instrumentation provenance, and the manual string-subclass boundary remain documented limitations.

### Pattern compilation and scope

`_lower_function_equations` (`desugar.py:299`) scans equations in source order. Its selected list retains only the first occurrence of each constructor, stops at the first variable final pattern, and preserves selected alternative order. A leading variable equation returns a directly curried RHS without generated case or aliases. The enumeration test independently computes the first applicable source index for Nil and Cons, then checks the generated alternative's marker body for all 120 sequences; it also checks absence of a match rather than inventing a fallback.

For constructor-led groups, each parameter has a fresh internal lambda binder, but the sole case scrutinee refers only to the final one. Earlier parameters are not inspected to choose a branch. `_lower_equation_body` (`desugar.py:263`) creates equation-specific aliases in parameter order. Their RHSs refer exclusively to fresh internal parameters, so simultaneous recursive scope does not capture another user alias. Duplicate source parameter binders are rejected before lowering. Cons fields are bound directly, head before tail, by `CoreConAlt`; lowering adds no cases/primitives demanding them.

A fallback's source variable aliases the original internal argument. Its fresh default binder is intentionally unused; substituting the inspected WHNF would change the representation available to a nonmemoizing CBN evaluator. This matches the later Core documentation and construction record. No artificial default is emitted for a non-exhaustive constructor group. A default retained after both list constructors is allowed by the current algorithm; this audit does not assume new semantics for non-list arguments or dynamic type errors.

Nested user scopes and shadowing remain explicit. Tests combine equation-specific parameter renaming, constructor fields, nested recursive let, lambda shadowing, and globals named `arg0`/`match0`. Generated `$arg*`/`$match*` names cannot occur in a valid Surface identifier. `CoreProgram` bindings remain one mutually recursive global scope, independently of source order; no dependency sorting or selective initialization is introduced.

### Fresh names

`src/lazy_lab/core/names.py:15–57`: each supply has a used-name set and per-prefix counters. `lower_program` creates one supply per call, shared across global groups. No global counter or UUID affects reproducibility. Generated names are valid Core identifiers; reserved ordinary words cannot be reserved as existing Core identifiers. A prefix such as `if` is valid because `$if0` is an internal identifier, not the reserved word `if`.

The used-name set also prevents collisions between overlapping prefixes: `fresh("arg1")` produces `$arg10`, subsequently skipped by `fresh("arg")`. Reservations are validated, idempotent, and respected after generation. Separate lowering calls deliberately restart the supply; combining their results or adding names in later Core passes requires reserving existing names or coordinating the supply. No unnecessary renaming of source binders was added.

## Findings

### F01 — Duplicate-binding diagnostic could escape as AttributeError

- **Severity:** Medium.
- **Location:** `src/lazy_lab/core/validation.py:171–175`, `_check_bindings`.
- **Evidence:** Before the fix, `validate_core_program(CoreProgram((CoreBinding("x", CoreInt(0)), CoreBinding("x", CoreInt(1), span="bad"))))` raised `AttributeError: 'str' object has no attribute 'start_line'`. The duplicate branch passed a truthy malformed span to formatting before normal span validation ran.
- **Impact:** Malformed Core input violated the `CoreValidationError` boundary; normally lowered valid programs are unaffected.
- **Resolution:** Use existing `_location(binding, span)` fallback, consistent with adjacent checks. Duplicate-binding diagnostics retain their prior precedence; this does not reorder all validation.
- **Verification:** Six cases cover program/local groups and absent/string/tuple spans, checking exception class, ancestor prefix and `span` attribute.
- **Status:** Fixed.

### F02 — Pruning can hide unresolved source references

- **Severity:** High, as a dependency for B02.9 design.
- **Location:** `desugar.py:309–321, 329–352`; specification §§6.3, 9.1, 9.2; Core guide, Pattern Matching.
- **Evidence:** `f x = 10` followed by `f [] = unknown` passes structural validation and lowers to `f = CoreLam("x", CoreInt(10))`. Surface still contains `unknown`; Core does not. A regression records this without adopting a diagnostic policy. Duplicate-constructor pruning can likewise remove references. Structural validation still checks every equation, including unreachable ones.
- **Impact:** A Core-only resolver cannot diagnose all original source references. The specification requires unknown-name rejection generally and permits unreachable equations, but does not explicitly exempt references in discarded equations or settle pass order. Operational unreachability alone does not authorize weaker static diagnostics.
- **Alternatives:** Resolve all Surface equations before lowering; retain discarded source information for a separate diagnostic pass; or explicitly revise the language policy to permit unresolved names in unreachable equations.
- **Recommendation:** Preserve the general unknown-name rule by checking every Surface equation before pruning, or an equivalent source diagnostic pass. B02.9 can still resolve executable Core separately. Specify selected-expression scope against the global group too.
- **Status:** Requires design decision. No name-resolution policy/pass was implemented.

### F03 — Aliases and cases require operational validation

- **Severity:** Medium.
- **Location:** `desugar.py:263–297, 361–379`; `src/lazy_lab/core/nodes.py:66, 87`; Core guide, Recursive bindings and Constructor inspection.
- **Evidence:** Separate equations `f a [] = 0` and `f b ys = b` introduce branch-local `CoreLetRec` aliases to internal parameters and an unused `$match*` default binder. No evaluator exists here.
- **Impact:** Original argument references and inspection structure are retained, but this does not establish neutral demand, sharing, allocations, blackhole behavior or error timing under an unspecified runtime.
- **Static justification and limits:** Fresh targets/distinct source binders establish lexical correctness. Under ordinary CBV application rules, aliases refer to argument values already obtained. Under nonmemoizing CBN forwarding, repeated alias demands can re-evaluate the original argument. Under CBNeed, forwarding may share a thunk or introduce an indirection. These are conditional explanations, not operational test results. Field/default binding must obey the WHNF contract.
- **Recommendation:** Specify alias/environment rules per strategy, including CBN nonmemoization, CBNeed update identity, CBV recursive initialization and constructor-field strictness. Test divergent unused arguments/fields, repeated demand, fallback after failed constructor matching, partial application, selected branches and cycles once an evaluator exists. Do not replace original-argument aliases with the case result merely as a simplification.
- **Status:** Open; requires operational tests/runtime contracts. No proven static lowering defect.

### F05 — Surface/Core string-subclass contracts disagree

- **Severity:** Low, limited to manual Python AST construction.
- **Location:** `src/lazy_lab/ast/validation.py:87–95, 187–197`; `src/lazy_lab/core/validation.py:79–88, 211–215`; name/operator copying in `desugar.py`.
- **Evidence:** With `class Identifier(str): pass`, `validate_expression(Var(Identifier("x")))` succeeds, but `validate_core_expression(lower_expression(Var(Identifier("x"))))` raises `CoreValidationError: Invalid Core identifier: 'x'`. Surface uses `isinstance(..., str)`; Core requires exact `str`. Operators/binders can have the same discrepancy.
- **Impact:** The general promise that every structurally valid manual Surface AST lowers to valid Core has an edge-case exception. Parser strings are exact builtins and unaffected.
- **Alternatives:** Require exact Surface strings; normalize accepted subclasses while building Core; or broaden Core's contract.
- **Recommendation:** Choose one scalar contract before expanding public manual construction support. Exact strings are simplest but change accepted Surface inputs; normalization preserves acceptance but needs a deliberate conversion policy. Do not silently change either validator here.
- **Status:** Requires design decision; documented in the Core input contract. No failing test was weakened or hidden with an expected-failure marker.

### F06 — Deep dataclass equality remains recursive

- **Severity:** Low for B02.8; relevant to future tooling.
- **Location:** Generated dataclass methods in `src/lazy_lab/ast/nodes.py` and `src/lazy_lab/core/nodes.py`.
- **Evidence:** Build 2,000 right-nested applications, validate Surface, lower twice and validate Core: all succeed. Comparing the two separate Core trees with `==` raises `RecursionError` in the manual probe. Dataclass hashing/representation also delegate recursively to children by construction; those operations were inspected, not all stress-tested here.
- **Impact:** Deterministic output exists, but naive deep equality assertions, cache keys, debugging or visualization may overflow. This is separate from repaired validation.
- **Recommendation:** Use iterative structural comparisons/serializers/renderers, as the new tests do. Do not redesign node equality or raise the process recursion limit in this milestone.
- **Status:** Open tooling limitation; no validation/lowering failure.

### F07 — Spans do not uniquely identify administrative work

- **Severity:** Medium for experimental instrumentation; no current execution defect.
- **Location:** `desugar.py:26–40, 263–297, 370–417`; `src/lazy_lab/core/nodes.py:9–14, 81–89`.
- **Evidence:** Generated aliases use source pattern names/spans, generated lambda chains share equation/binding spans, list-spine nodes share literal spans, and `CoreConAlt` has binder strings without individual head/tail spans. Spans are excluded from equality. Tests independently check alias/case/default/lambda provenance.
- **Impact:** Current source correspondence is adequate, but neither `$` prefixes nor spans identify all compiler administration. Counting all bindings/allocations as source work can distort strategy comparisons; source-named aliases have no explicit origin tag.
- **Recommendation:** Define attribution before experiments. Options include raw Core versus attributed source event streams, or an external provenance map. Specify alias/default costs. Retain pattern/equation locations for errors; add finer binder provenance only for a concrete diagnostic need.
- **Status:** Requires design decision for instrumentation. No IR redesign was made.

### F08 — Some existing lowering tests had weak assertions

- **Severity:** Low.
- **Location:** `tests/core/test_desugar.py`, former `test_multiple_equations_are_not_silently_discarded`, `test_constructor_patterns`, large-list test.
- **Evidence:** The former test only called lowering on two variable equations, although the implementation deliberately discards the second. Constructor smoke tests did not validate outputs; the large-list test checked only the first constructor.
- **Impact:** Those tests alone could miss dropped/reordered data or imply the wrong contract. Other existing pattern tests already provided stronger first-match coverage; this is a test-quality gap, not evidence of a compiler bug.
- **Resolution:** Renamed/asserted the variable-equation test accurately; constructor smoke cases now validate Core. Added complete large-list/deep-shape checks, generated-span checks and exhaustive short-sequence routing checks.
- **Status:** Fixed.

## Robustness and complexity

| Path | Assessment and evidence |
| --- | --- |
| Surface validation | Explicit stack of suspended child iterators preserves DFS/check order and nearest spans. No recursive expression/pattern-helper path remains. Existing 2,000-depth valid/invalid tests pass with 100% line/branch coverage. |
| Parser | Recursive constructs share the documented 64-context budget. Sibling list elements and left-associative operators/applications do not accumulate it. Boundary/location tests pass. This is not an AST-depth limit. |
| Lowering | Iterative postorder, with pending/results stacks. Each expression is expanded/built once. Calling `_children` twice examines immediate edges twice, not entire subtrees repeatedly. |
| Currying/list construction | Reverse loops, no recursive calls; all 2,000 parameters/elements checked, not just absence of exceptions. |
| Local bindings/applications | 2,000-deep RHS/body nesting and right-nested applications validated/lowered as expressions and programs, then Core-validated. Existing tests also cover left-associated operators and 1,500 nested let bodies. |
| Global grouping | `groupby` preserves consecutive source order. Groups are materialized/scanned linearly. Surface rejects separated groups, mixed categories, duplicate values and inconsistent arities. Tests cover 2,000 groups and 2,002 equations. |
| Core validation | Explicit node/location stack; large generated trees pass and a 2,000-depth invalid descendant reports its inherited location. F01 fixes escaping diagnostic formatting. |
| Empty/no-main programs | Valid; lower to ordered Core bindings, including the empty tuple. No implicit main, fallback, evaluation or wrapper is synthesized. |

For ordinary finite trees and bounded-cost names/scalars, validation/lowering are O(n) in nodes, edges and parameter/binder entries, with O(n) worst-case storage. Hash-set checks have ordinary expected constant lookup cost. Output size is included: list constructors, aliases and currying add nodes. No avoidable quadratic subtree traversal was found. This is a code-level argument, not a timing benchmark. Arbitrary-precision integer work and pathological Python subclasses are outside the bounded-scalar assumption. Shared DAG subtrees are visited per occurrence; cycle detection/graph memoization are not promised.

Lowering requires validated finite, acyclic Surface trees. It rejects wrong root categories with `TypeError` and explicitly detected unsupported cases with `DesugaringError`, but is not a complete malformed-input validator. For example, unvalidated `Program((FunctionEquation("f", (), IntLiteral(0)),))` can reach `IndexError`; `Application(None, IntLiteral(0))` can reach `AttributeError`. Surface validation rejects both before lowering. These are precondition violations, not failures on supported valid input. The contract is now explicit. No broad exception catch, global recursion-limit change or new depth limit was added.

## Outstanding semantic risks

Valid Core establishes representability, not dynamic equivalence. Runtime policies must preserve non-strict variable patterns under CBN/CBNeed, inspect only outer constructors for selection, avoid forcing fields merely to bind them, evaluate only selected branches, preserve repeated demand under CBN and sharing under CBNeed, and initialize recursive environments consistently under CBV.

Aliases are lexically sound but can add environment entries, indirections, thunks or bookkeeping. The unused default binder and original-argument alias are intentional representation choices. Instrumentation must not silently classify their costs as source computation or automatically memoize CBN inspection. Neither unconditional strategy equivalence nor a proven runtime semantic defect follows before operational rules exist.

Checking discarded equations is an immediate static-design risk (F02). String subclasses and recursive dataclass utilities are narrower API/tooling limitations (F05/F06), not failures on parser-produced trees.

## Recommendations for B02.9

1. Decide diagnostic domain/pass order first: preferably check every source equation before pruning, while allowing executable Core resolution separately. Add acceptance tests for unknown names in unreachable equations/branches.
2. Define lexical environments for global groups, simultaneous recursive let, unary lambdas, constructor binders and default binders. Global order must not limit visibility. Resolve internal/source names by scope, not prefixes. Resolve selected expressions against the program environment.
3. Keep resolution and supporting traversals iterative; avoid recursion through free-variable collection, pretty printing, equality-based memoization or diagnostics.
4. Settle exact-string contracts deliberately, testing identifier/operator/binder subclasses while preserving supported ordinary-source behavior.
5. Define provenance and metric attribution before comparing strategies, including alias/case/default events. An external side table is an option; no IR redesign is required by this audit alone.
6. Carry forward an operational matrix for unused divergent arguments/fields, fallback re-demand, recursion, error timing, partial application and CBN/CBNeed sharing. Specify constructor matching on non-list values without inferring runtime policy from structural validation.
7. Reserve existing generated names in future Core transformations; deterministic per-call counters do not ensure uniqueness across combined independent runs.
